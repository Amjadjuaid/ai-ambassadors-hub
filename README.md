# سفراء الذكاء الاصطناعي — AI Ambassadors Hub

تطبيق ويب خفيف بدون أي أدوات بناء (build tools) — ملفات HTML/CSS/JS عادية.
قاعدة البيانات: Firebase Firestore. الاستضافة: GitHub Pages.

---

## 1) إعداد قاعدة بيانات Firebase

1. افتح https://console.firebase.google.com وسجّل الدخول بحساب Google.
2. **Add project** → اختر اسمًا → أكمل الخطوات (يمكن تعطيل Google Analytics، غير مطلوب).
3. من القائمة الجانبية: **Build → Firestore Database** → **Create database** → اختر أي موقع قريب (مثال: `eur3` أو `me-central1` إن توفر).
4. بعد الإنشاء، افتح تبويب **Rules** داخل Firestore، واستبدل المحتوى بمحتوى ملف `firestore.rules` المرفق هنا، ثم اضغط **Publish**.
5. من **Project settings** (⚙️ بجانب Project Overview) → مرّر لأسفل إلى **Your apps** → اضغط أيقونة الويب `</>` → سمِّ التطبيق → **Register app**.
6. ستظهر لك بيانات إعداد (`firebaseConfig`) — افتح ملف **`firebase-config.js`** في هذا المجلد، وضع القيم الحقيقية. احفظ الملف.

هذا كل شيء من جهة قاعدة البيانات — لا حاجة لأي كود خادم (backend) إضافي.

---

## 2) النشر (GitHub Pages)

الموقع مستضاف عبر GitHub Pages من فرع `main`. أي تعديل يُدفع إلى `main` يُنشر تلقائيًا بعد دقائق قليلة على:

`https://<المستخدم>.github.io/<اسم-المستودع>/`

لا حاجة لأي خطوة بناء (build) — الملفات الثابتة تُقرأ وتُنشر كما هي.

---

## 3) كود وصول مساحة السفراء

الكود الافتراضي محفوظ في `constants.js`:
```js
const AMBASSADOR_ACCESS_CODE = "AMB-2026";
```
**غيّره قبل الاستخدام الفعلي** إلى كود من اختيارك، وشاركه مع سفراء الذكاء الاصطناعي خارج نطاق رابط الموقع (مثال: عبر بريد أو Teams). **تنبيه مهم**: هذا الكود يخفي واجهة الاستخدام فقط لمنع الدخول العرضي — وليس طبقة حماية حقيقية للبيانات (راجع التنبيه في `firestore.rules`). لا تُدخل بيانات سرية في أي طلب أو ملاحظة.

---

## 4) تسجيل السفراء

لا توجد بيانات سفراء مزروعة مسبقًا. أول دخول لأي سفير يتم من **بوابة السفراء → سفير جديد؟** بإدخال الاسم والإدارة والمسار وكود الوصول — يُنشئ ذلك ملف السفير في قاعدة البيانات مباشرة. بعد التسجيل، يختار السفير اسمه من القائمة في كل مرة دخول لاحقة.

---

## 5) بنية الملفات

| الملف | الوظيفة |
|---|---|
| `index.html` | هيكل الصفحة والتحميل |
| `styles.css` | كل التصميم |
| `constants.js` | القوائم الثابتة (الحالات، الإدارات، المسارات، إلخ) — عدّل هنا أولًا لأي تغيير في الخيارات |
| `firebase-config.js` | بيانات ربط مشروعك على Firebase |
| `firebase-init.js` | تهيئة الاتصال بـ Firebase |
| `data.js` | **طبقة الوصول للبيانات فقط** — كل استدعاءات قاعدة البيانات تمر من هنا (التحديات، طلبات المشاركة، السفراء، الأرقام المرجعية) |
| `app.js` | التوجيه (routing) وكل واجهات العرض والتفاعل |
| `firestore.rules` | قواعد الوصول لقاعدة البيانات |

---

## 6) قيود معروفة

- **لا يوجد تسجيل دخول حقيقي**: أي شخص يملك رابط الموقع يمكنه تقنيًا قراءة كل الطلبات (بما فيها ملاحظات الفريق الداخلية) عبر أدوات المطوّر في المتصفح، حتى دون إدخال كود الوصول — الكود يخفي الواجهة فقط. لمنع ذلك فعليًا يلزم مصادقة حقيقية (Firebase Auth).
- **لا نسخ احتياطي تلقائي**: البيانات في Firestore تبقى ما لم تُحذف يدويًا؛ لأخذ نسخة احتياطية استخدم تصدير Firestore من الكونسول.
- **لا إمكانية حذف من الواجهة**: لا يستطيع السفراء حذف التحديات أو طلبات المشاركة أو سجلاتها — الإغلاق يتم عن طريق تغيير الحالة فقط.
